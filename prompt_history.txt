KEY PROTOCOL DETAILS EXTRACTED:
-------------------------------
- UVR1611 uses 488 Hz display clock
- Bit duration: 2.048 ms (2048 µs)
- Half-bit duration: 1.024 ms (1024 µs)
- Data is XOR'd with clock, then inverted by output transistor
- SYNC: 16 high bits without start/stop bit
- Byte format: 1 start bit (0), 8 data bits (LSB first), 1 stop bit (1)
- Frame: 65 bytes total (SYNC + 64 data bytes including checksum)
- Device ID: 0x80, inverted: 0x7F
- Checksum: sum of bytes 1-63 mod 256

WHAT WAS DONE:
--------------
Complete architectural refactor from monolithic to pipeline-based design.

NEW ARCHITECTURE:
-----------------
1. RMT Hardware -> Edge Circular Buffer (1024 entries, ~1.5 frames)
2. Bit Extractor Task -> Bit Queue (1024 entries)
3. Manchester Decoder Task -> Frame Queue (3 frames)
4. Main Task -> Displays frames and statistics

COMPONENTS CREATED:

1. Edge Circular Buffer (edge_buffer_t):
   - Stores pulse durations with level (HIGH/LOW)
   - Size: 1024 entries (~1.5 frames worth)
   - Lock-free single-producer/single-consumer safe design
   - Mutex for batch operations from RMT callback
   - Binary semaphore for data-ready signaling

2. RMT Receive Task (rmt_receive_task):
   - Priority 10 (highest)
   - Continuously receives RMT symbols
   - Copies symbols to edge circular buffer
   - Signals bit extractor when data available

3. Bit Extractor Task (bit_extractor_task):
   - Priority 8
   - Reads edges from circular buffer
   - Classifies pulses: SHORT (~1024us), LONG (~2048us), INVALID
   - Counts half-bits and extracts bits at 2-half-bit boundaries
   - Handles gaps (>5ms) by resetting state
   - Outputs bit_entry_t to bit_queue

4. Manchester Decoder Task (manchester_decoder_task):
   - Priority 6
   - State machine: HUNTING_SYNC -> IN_BYTE
   - Detects SYNC: 16+ consecutive 1s (or 0s if inverted)
   - Handles polarity inversion automatically
   - Assembles bytes: start(0) + 8 data bits (LSB first) + stop(1)
   - Validates checksum (sum of bytes 0-62 mod 256)
   - Outputs dlbus_frame_t to frame_queue

5. Main Task (app_main loop):
   - Receives frames from frame_queue
   - Prints decoded frames with key fields
   - Shows timestamp if available
   - Prints pipeline statistics every 10 seconds

DATA STRUCTURES:
----------------
- edge_t: {duration, level}
- bit_entry_t: {value, is_sync}
- dlbus_frame_t: {data[64], length, valid, timestamp}

BUFFER SIZING:
--------------
- Frame = 64 bytes x 10 bits x ~2 pulses/bit = ~1280 pulses
- Edge buffer: 1024 entries (safety margin)
- Bit queue: 1024 entries
- Frame queue: 3 entries

STATISTICS TRACKED:
-------------------
- stat_edges_received
- stat_bits_extracted
- stat_syncs_detected
- stat_frames_decoded
- stat_frames_valid
- Buffer fill levels

BENEFITS OF NEW ARCHITECTURE:
-----------------------------
1. Separation of concerns - each task has single responsibility
2. Better buffering - circular buffer prevents data loss
3. Async processing - tasks run independently
4. Easier debugging - statistics show pipeline health
5. More robust - gaps and noise handled gracefully
6. Extensible - easy to add processing stages

USER PROMPT:

PROBLEM DISCOVERED:
-------------------
ESP32 RMT peripheral has a fundamental limitation without DMA:
- Maximum 512 symbols (8 memory blocks × 64 symbols)
- Full DL-Bus frame needs ~656 symbols (16 SYNC + 64 bytes × 10 bits)
- Could only capture ~60 bytes (512 symbols) before buffer filled
- Double-buffering attempted but gaps between captures caused data loss
- ESP32-WROOM-32 does NOT support DMA for RMT (only ESP32-S2/S3/C3)

SOLUTION IMPLEMENTED:
---------------------
Replaced RMT peripheral with GPIO interrupt-based edge capture:

1. GPIO Interrupt Handler (gpio_isr_handler):
   - Fires on every edge (rising AND falling) using GPIO_INTR_ANYEDGE
   - Captures timestamp via esp_timer_get_time() (microsecond precision)
   - Calculates pulse duration since last edge
   - Stores directly to circular buffer
   - NO BUFFER SIZE LIMIT - limited only by software buffer (2048 entries)
   - Fast execution (~1ms pulses = plenty of time for ISR)

2. Removed all RMT code:
   - No rmt_rx.h include
   - No RMT channel, callbacks, or tasks
   - No hardware buffer limitations

3. Pipeline now:
   GPIO ISR → Edge Buffer → Bit Extractor Task → Manchester Decoder → Frames

RESULTS:

- Device ID: 0x80 (UVR1611) ✓

================================================================================

USER PROMPT:
------------
[User provided device monitor output showing two issues:]
1. "Guru Meditation Error: Core 0 panic'ed (Cache error). Cache disabled but
   cached memory region accessed" - Crash during NVS flash init
2. After fixing crash: DL-Bus reading became unreliable with >90% error rate
   (was <1% before WiFi/MQTT implementation)

PROBLEMS IDENTIFIED:
--------------------

Problem 1: Cache Error Crash
- GPIO ISR called gpio_get_level() which accesses flash memory
- During nvs_flash_init(), flash cache is disabled for read operations
- When GPIO interrupt fired during NVS init, ISR tried to access flash → crash

Problem 2: WiFi Timing Interference
- WiFi interrupts cause variable latency in GPIO ISR execution

ROOT CAUSE ANALYSIS:
--------------------
Room sensor encoding uses 9 bits, not 8:
- Low byte (8 bits) + bit 0 of high byte (1 bit) = 9 bits
- Bits 1-3 of high byte contain operating mode (not temperature)
- Range: -51.1°C to +51.1°C (values -511 to +511)

The original bug (iteration 3) was reading 12 bits which included mode bits.

- OLD: int16_t raw_value = low_byte;
- NEW: int16_t raw_value = low_byte | ((high_byte & 0x01) << 8);
- Two's complement adjusted from 256 to 512 for 9-bit values

=== ARCHITECTURE OVERVIEW ===

The project implements a UVR1611 DL-Bus to MQTT gateway with Home Assistant
integration. It uses a pipeline architecture for signal processing on a
D1 Mini ESP32.

CURRENT DATA FLOW:
------------------
1. GPIO26 captures DL-Bus signal edges via ISR (pinned to Core 1)
2. Edge buffer (circular, 2048 entries) holds pulse durations
3. Bit Extractor task classifies pulses, extracts bits
4. Manchester Decoder task detects SYNC, assembles 64-byte frames
5. Frame queue passes valid frames to main task
6. Main task parses sensors/outputs and publishes via MQTT

CORE ALLOCATION:
----------------
- Core 0: WiFi stack, MQTT client, main task
- Core 1: GPIO ISR, Bit Extractor, Manchester Decoder (timing-critical)

NAME FILTERING LOGIC:
---------------------
Names are DISABLED (not published/discovered) if:
- NULL or empty string
- Contains only "-" characters (like "---")
- Contains no letters (A-Z, a-z) and no digits (0-9)

Example:
| Name            | config_is_name_enabled() | Published? |
|-----------------|--------------------------|------------|
| "T.Heizkr.VL"   | true                     | Yes        |
| "WMZ1 Leistung" | true                     | Yes        |
| "---"           | false                    | No         |
| ""              | false                    | No         |
| "- - -"         | false                    | No         |
